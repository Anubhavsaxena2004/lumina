# Kumkum Payal (कुंकुम पायल) — Jewellery Accounting & Inventory System

An enterprise-grade, mobile-responsive accounting and inventory management system designed specifically for jewellery trading businesses and artisan manufacturers (featuring Polish and Meena / Enamel job-work tracking).

## Technology Stack

- **Frontend**: Next.js 16 (App Router), React 19, TypeScript, Tailwind CSS, Lucide Icons
- **Backend API**: Node.js, NestJS, TypeScript, OpenAPI / Swagger documentation
- **Database**: PostgreSQL 16 with 17 relational tables, strict numeric precision, and append-only trigger protection
- **Queue & Scheduling**: Redis 7 + BullMQ for asynchronous jobs and daily overdue payment reminders
- **Bill Generation**: Headless HTML-to-JPG bill rendering using Puppeteer and Sharp
- **Messaging**: WhatsApp Business Cloud API with pluggable provider architecture (Cloud API & Mock Provider)
- **Containerization**: Multi-stage Docker & Docker Compose with non-root security

## Quick Start with Docker

```bash
# 1. Clone the repository and configure environment
cp .env.example .env

# 2. Start all services (PostgreSQL, Redis, API, Worker, Next.js Web App)
docker compose up --build

# 3. Check API health
curl http://localhost:4000/health
```

The services will be accessible at:
- **Web Application**: [http://localhost:3000](http://localhost:3000)
- **REST API & Swagger Docs**: [http://localhost:4000/api/docs](http://localhost:4000/api/docs)
- **PostgreSQL**: `localhost:5432` (`kumkum_payal`)
- **Redis**: `localhost:6379`

## Core Architecture Principles

1. **Server Clock Immutability**: All transaction timestamps (`entry_at`) are unconditionally generated by the database clock (`now()`). Request payloads attempting to supply dates or timestamps are rejected.
2. **Double-Layer Staff Isolation**: Staff members can only insert new records and view entries created by their own user ID (`created_by = current_user.id`). Staff cannot edit or delete any records.
3. **Append-Only Ledgers**: The `ledger_entries`, `stock_movements`, and `audit_log` tables are protected by database triggers that reject all `UPDATE` and `DELETE` queries. Any owner corrections generate reversing credit/debit or stock delta rows.
4. **Unified Multi-Line Accounting**: Sales and purchases record pieces and weight in kilograms (`numeric(12,3)`) alongside unit rates, posting to customer/supplier ledgers and stock registers within a single atomic database transaction.
5. **Overdue Payment Automation**: Daily BullMQ cron inspects unpaid invoices past their due dates, respects owner-configured `repeat_days`, sends individual customer WhatsApp reminders, and delivers a consolidated daily dues summary to the owner.
